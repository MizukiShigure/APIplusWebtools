# 数字人工作流

## 入口与配置

启动工作台后，打开 `http://127.0.0.1:4198/?page=avatarWorkflow`，或在侧栏选择“数字人工作流”。原“数字人”批量任务页保留。

1. 在“音色库”新增音色名称、提供方音色 ID、语言和备注。
2. 在“形象相册”上传 PNG/JPEG/WebP 图片。编辑形象可以绑定多个音色，并指定默认音色；绑定仅由用户设定，不进行人脸或声音身份推断。
3. 使用 Kling 时无需额外 RunningHub 配置。使用 RunningHub 时在“工作流”中填写配置名称、应用链接，粘贴节点 payload 并解析，检查图片、音频、提示词等动态绑定。
4. RunningHub API Key 可使用工作台侧栏的全局配置，也可给单个工作流设置独立 Key。浏览器只显示是否已配置，不回传已保存的 Key。
5. “设置”可以导入相邻目录 `speech-avatar-subtitle-tool/local-config.json` 的音色和工作流。旧文件不修改，导入会保留私有备份；同一记录重复导入不覆盖已保存内容。

## 制作流程

标题栏右侧是形象相册、音色库、工作流、设置四个管理小标签；窄屏时在标题下方换行，仍留在标题栏内。标题栏下方是“语音 / 数字人 / 字幕”三个大的制作子标签页，一次只显示其中一个，不与管理入口混排。各页分别提交、检查结果，不会自动串行生成：

1. **语音**：左边填写文本、试听结果；右边设置音色、模型、语言及声音参数，点击“生成语音”。已有音频可上传到“已有音频 / 音频调整”，独立调整速度和裁切。
2. **数字人**：左边选择或上传音频、选择形象；右边填写表演提示词、选择工作流，点击“生成数字人”，只生成视频，不会重新合成语音。
3. **字幕**：左边上传音频/视频或填写地址，并按需填写原文；点击“生成字幕”。右边可查看、编辑和下载 SRT。编辑仅修改当前页面下载内容，原生成文件和共享历史不被覆盖。

音频结果可点击“用于数字人”“用于字幕”或“用于音频调整”，视频结果可点击“用于字幕”。这些操作只填入目标页并切换到对应的大标签，不自动生成；替换已有素材时会确认。从相册选择“用于制作”会回到数字人标签。切换标签不会清空草稿、选中的结果或已编辑的字幕；多个结果可通过各页的“结果记录”选择。

提交后在下方查看步骤状态与结果。任务执行在 4198 本地服务内，关闭标签页不会终止执行。服务重启后已有远端任务 ID 的任务继续轮询；提交结果不明时不会自动重发，需要核查提供方任务，避免重复扣费。

成功的音频、视频和字幕记录自动进入工作台生成缓存，保留文本、表演提示词、素材引用、音色和来源。可从历史记录“添加到生成队列行”回到数字人工作流复用输入。

## 本地共享与数据

所有浏览器和 Agent 使用同一个 `API_BATCH_DATA_DIR`。新增内容位于该目录的 `avatar-workflow` 子目录：配置/任务记录、相册原图、必要的音频和字幕中间文件、私有迁移备份。

- 相册图片按 SHA-256 内容去重；删除相册条目不破坏已有任务/历史对原图的引用。
- 生成视频默认只保存远端 URL 和记录，不自动完整下载。
- 配置按条目和版本保存。另一浏览器修改过同一条目时返回 409，当前草稿不会直接覆盖新版本。
- Agent 可以读取和新增资料、提交任务；修改和删除已有资料仅允许手动浏览器操作。
- 共享数据、Key、个人素材不会进入便携包或 Git。备份时请备份整个共享数据目录，而不是浏览器缓存。

## 可选工具

音频调整需要 FFmpeg。字幕需要 Python、FFmpeg、`subtitle_service.py` 和已缓存的字幕模型。在“设置”中填写 `python`、`ffmpeg`、`subtitleService` 的实际本机路径并检查状态。

缺少这些工具不会阻止基础语音/数字人制作，但依赖相应工具的步骤不可用。RunningHub 节点需要动态时长或尺寸时，服务先读取实际素材元数据；无法获取时停止并报错，不沿用 payload 中的旧值。

便携包不附带 Python、FFmpeg、字幕模型或个人 Key，接收者需要按其使用步骤配置可选依赖。原 4208 工具不受本次整合影响。

## Agent 与开发

Agent 使用 `skills/api-plus-agent/SKILL.md`，数字人扩展见 `skills/api-plus-agent/references/avatar-workflow.md`。新增命令包括 `avatar-library`、`avatar-upload`、`avatar-submit`、`avatar-status`、`avatar-wait`。

实现分为 `avatar-workflow-store.cjs`（版本化资料）、`avatar-workflow-media.cjs`（提供方/本地处理适配）、`avatar-workflow-service.cjs`（鉴权、持久任务与历史）、`avatar-workflow-ui.js/css`（页面）、`avatar-workflow-production.js`（独立生产分区与结果传递）。`runninghub-shared.js` 将原全局配置界面连接到同一资料库。

运行 `npm test`。浏览器测试需要 Playwright 与 Chrome，可通过 `PROMPT_LIBRARY_PLAYWRIGHT` 和 `PROMPT_LIBRARY_BROWSER_CHANNEL` 指定。测试使用隔离数据和模拟提供方，不应调用收费接口。
