# Kling 3.0 Omni、Seedance 4K 与主体库设计

日期：2026-07-16

## 1. 目标与发布顺序

本次工作分成两个可独立回退的发布阶段：

1. 主线稳定版：完成 Kling 3.0 Omni、Seedance 2.0 4K、页面布局收口、错误复制、便携包隐私检查和后台常驻启动。
2. 主体库分支：在主线稳定版打 tag 后，从该版本创建独立分支，重构主体库并把主体选择接入 Kling Omni 与 Seedance 2.0。

主体库分支不在验证完成前合入主线。两阶段均推送到 `git@github.com:MizukiShigure/APIplusWebtools.git`。

## 2. 不变约束

- 多模态生视频继续使用现有表格页面，不新增独立 Kling 页面。
- 用户仍在同一参考栏选择、上传、粘贴、拖入和复制素材。
- 所有模型请求继续通过公司 `API Base` 中转，不在页面中要求供应商 API Key。
- 浏览器缓存、队列、表单内容、API Key、RunningHub 配置、主体数据和历史记录均为本机用户数据，不进入 GitHub 或便携包。
- 生产代码采用局部修改；不重写现有大文件，也不改动无关模型。

## 3. 主线稳定版架构

### 3.1 模型能力配置

在现有模型配置中保留 `Kling 3.0 Omni` 选项，并把当前“待配置”的 builder 替换成正式能力配置：

- 公司中转创建路径：沿用现有 `/kling_3_omni_video`。
- 公司中转查询路径：沿用现有 `/kling_3_omni_video_query`。
- 模型版本：`kling-3-omni`。
- 比例：`16:9`、`9:16`、`1:1`。
- 清晰度：`720p`、`1080p`、`4k`。
- 时长：3 到 15 秒的整数。

模型配置继续提供 `validate(row)` 与 `build(row)` 两个边界：验证函数只负责给用户可读错误，构建函数只负责生成供应商形状的 payload。这样可以单独测试字段映射，不依赖真实接口。

### 3.2 Kling 3.0 Omni 请求映射

请求体固定为：

```json
{
  "contents": [],
  "settings": {
    "resolution": "1080p",
    "duration": 5,
    "audio": "native",
    "multi_shot": false,
    "aspect_ratio": "16:9"
  },
  "options": {}
}
```

`contents` 按下面的顺序稳定生成：

1. Prompt：`{ "type": "prompt", "text": "..." }`。
2. 普通参考图片：依参考栏顺序映射成 `refer_image`，ID 为 `image_1`、`image_2` 等。
3. 参考视频：最多一个，映射成 `feature_video`，ID 为 `video_1`。
4. 可灵主体：映射成 `{ "type": "element", "element_id": "...", "id": "element_1" }`。

页面原有 `@1`、`@2` 可视编号在提交时转换为对应供应商 ID，用户不需要手写 URL。普通音频不是 Kling Omni 支持的输入类型；选中 Kling 时若参考栏包含音频，提交前直接提示并阻止请求。

为保持页面不变，本阶段不增加多镜头开关，`multi_shot` 固定为 `false`。音频规则为：用户关闭声音时传 `off`；只有图片/主体时默认传 `native`；含 `feature_video` 时传 `original`。以后若增加多镜头 UI，再单独实现多镜头与音频组合约束。

提交前验证：

- Prompt 不得为空，最长 3072 字符。
- 图片必须有可访问 URL；已知尺寸时校验边长至少 300 px、比例 0.4 到 2.5、文件不超过 50 MB。
- 参考视频最多一个；已知元数据时校验 MP4/MOV、3 到 15.5 秒、宽高 700 到 4553 px、像素不超过 8,294,400、比例 0.4 到 2、帧率 24 到 60。
- 尺寸、清晰度和时长必须属于当前版本枚举。
- Kling 主体必须有成功状态和非空 `element_id`。

前端无法获知的编码、帧率或远程文件大小不伪造结论，由后端继续校验，并把完整错误保存到行状态。

### 3.3 Seedance 2.0 4K

图文生视频与多模态生视频共用同一版本级能力规则：

- Seedance 2.0 普通版：`480p`、`720p`、`1080p`、`4k`。
- Seedance 2.0 Fast：`480p`、`720p`，不显示 1080p 或 4K。
- 其他 Seedance 版本维持已有枚举。

切换模型版本时沿用现有“保留相同值，否则选最接近值”的规则。正式 payload 在 body 中传 `resolution: "4k"`，不把 4K 仅写进 Prompt。4K 返回可能是 10bit H.265；预览失败时保留原始链接和下载能力，并显示浏览器解码兼容提示。

### 3.4 页面布局收口

侧边栏分为三个稳定区域：

- 顶部：品牌、API Base、RunningHub 状态。
- 中部：任务类型列表，独立纵向滚动。
- 底部：缓存、导出、清理等固定操作。

主表格只在内容区滚动。不同窗口宽度下通过固定最小列宽与横向滚动保证控件不重叠，不按视口宽度缩放字体。

行布局调整：

- 序号/操作列中的勾选、序号、提交、取消、复制、删除纵向排列。
- 模型与模型版本维持同一紧凑列；尺寸、清晰度、时长维持同一紧凑列。
- 状态正文为单行省略，最大约 10 个中文字符宽；状态徽标仍显示任务计数。
- 行存在错误时显示 `复制报错信息`，复制完整错误文本；页面不再直接铺开长错误。
- 处理中仅禁用提交和删除；复制行仍可用。

### 3.5 后台常驻与快捷启动

新增 PM2 配置文件和统一启动脚本：

- 启动器依次查找项目本地 PM2、PATH 中 PM2、Windows npm 全局 PM2。
- 找到 PM2 时以固定进程名 `api-plus-webtools` 启动 `server.cjs`，重复点击不会重复创建进程。
- 未找到 PM2 时使用隐藏 Node 进程作为便携回退，仍可正常打开工具。
- 停止脚本优先执行 PM2 stop/delete，回退模式才按端口停止本地服务。
- 快捷启动入口只引用项目目录，不写死当前用户的 Codex runtime 路径。

## 4. 主体库分支架构

### 4.1 本地数据模型

主体记录持久化到独立 IndexedDB store，结构如下：

```js
{
  id,
  name,
  description,
  referenceType,
  images: [{ id, role, name, url, preview, width, height, size }],
  videos: [{ id, name, url, preview, width, height, duration, size }],
  voices: [{ id, name, url, preview, duration, size, voiceId }],
  kling: {
    status,
    createTaskId,
    elementId,
    elementVoiceId,
    error,
    updatedAt
  },
  createdAt,
  updatedAt
}
```

本地记录与供应商主体状态分开。只有本地素材的主体可立即用于 Seedance；只有 `kling.status === "ready"` 且存在 `elementId` 的主体可用于 Kling Omni。

旧主体库 localStorage 数据在首次打开时只迁移可识别字段，不删除旧数据；迁移完成后写入版本标记，避免重复导入。

### 4.2 可配置公司中转契约

主体库页面提供折叠的 `可灵 Elements 中转配置`：

- 创建路径默认 `/kling_element_create`。
- 查询路径默认 `/kling_element_query`。
- 删除路径默认 `/kling_element_delete`。

三个路径均可编辑，保存到当前浏览器本地设置，不进入源码包。请求仍自动拼接左侧 `API Base`。

创建请求使用官方字段形状：

- 图片主体：`reference_type: "image_refer"`，1 张 `frontal_image` 加 1 到 3 张 `refer_images`。
- 视频主体：`reference_type: "video_refer"`，只提交 1 段符合规则的视频。
- 已有可灵音色时可传 `element_voice_id`。
- `element_name` 最长 20 字符，`element_description` 最长 100 字符。

创建后保存 `task_id` 并轮询配置的查询路径；成功后保存 `element_id`。404 显示“公司中转未开放该路径”，不会继续尝试一串猜测路径。删除先请求公司中转；供应商删除成功后再清除远端 ID，本地记录是否同时删除由用户明确选择。

### 4.3 主体库页面

主体库保持表格结构，列为：

- 勾选/序号
- 主体名与描述
- 图片参考
- 视频参考
- 音色参考
- 可灵状态与 `element_id`
- 操作

创建区按 `图片主体` 与 `视频主体` 切换素材规则。图片主体要求用户指定正面图，其余图片作为差异参考；视频主体只允许一段视频。素材继续复用现有选择、上传、粘贴、拖入和复制交互。

### 4.4 多模态页主体选择

参考栏增加 `选择主体` 按钮，不新增表格列。点击后打开主体选择窗口：

- 先选择一个或多个主体。
- 展开主体后分别勾选需要的图片、视频和音色。
- Kling Omni 模式只允许选择已有 `element_id` 的可灵主体，未就绪项显示原因并禁用。
- Seedance 模式允许选择任何本地主体素材。

行数据增加 `subjectBindings`，记录主体 ID 与已选素材 ID。复制行时复制绑定关系；删除参考素材时同步取消对应绑定；切换到不支持主体的模型时保留绑定但不提交，并在界面提示。

### 4.5 Seedance 主体注入

确认主体选择后：

1. 把勾选的图片、视频和音频按主体顺序加入当前行参考栏，复用已有 URL，不重复上传。
2. 根据参考栏最终编号生成可见前缀，例如：

```text
@1、@2 是【小满】的形象参考；@3 是【小满】的音色参考。
```

3. 把前缀放在用户 Prompt 最前面。

每行保存上一版自动前缀。主体或参考顺序变化时，只替换由工具记录的旧前缀，不删除用户自己输入的相似文字，保证操作幂等。视频归入形象参考；图片、视频、音色可分别取消勾选。

### 4.6 Kling 主体注入

Kling Omni 构建请求时，把每个已就绪主体转成 `element` content，并按顺序分配 `element_1`、`element_2`。主体素材本身不重复作为普通参考图提交，除非用户在参考栏中另外显式选择了这些素材。

提交前若主体已被远端删除、创建失败或缺少 `element_id`，行保持待处理并显示可复制的具体错误，不发送降级请求。

## 5. 错误与状态处理

- 前端参数错误：提交前阻止，状态显示短摘要，完整内容可复制。
- 公司中转 404：明确标记为路由未开放，并显示实际请求路径。
- 供应商 4xx：保留供应商 code、param、request_id。
- 供应商 429/5xx：保留原始错误，不自动无限重试；仍由现有队列并发控制负责后续任务。
- 查询超时：沿用 30 分钟规则；本地取消不伪装为供应商取消成功。
- 页面刷新：恢复队列与本地状态时不把空历史覆盖到 IndexedDB 或磁盘备份。

## 6. 隐私与分发

Git 和便携包只包含工具本体。打包使用显式白名单，并创建空的 `data/` 与 `runtime/` 目录。下列内容必须被排除：

- `data/history.json` 与 AppData 历史备份
- localStorage / IndexedDB 数据
- API Key、RunningHub 配置、Elements 路由的用户改值
- 当前队列、Prompt、上传素材、主体库记录
- 日志、PM2 dump、PID 文件、测试临时文件和规划笔记

回归测试会实际构建一个临时便携包并检查归档清单与敏感文本模式，而不只检查 `.gitignore`。

## 7. 测试与验收

### 7.1 自动测试

- Kling Omni builder：图片、视频、主体、@编号、4K、3/15 秒边界、音频拒绝和错误组合。
- Seedance 版本能力：普通版出现 4K，Fast 不出现；切换版本时相近值回退。
- 主体 payload：图片主体、视频主体、音色绑定、路由 404、创建轮询和删除。
- Seedance 主体：多素材勾选、自动前缀、重新排序、取消选择、复制行和幂等更新。
- UI 结构：侧栏三段布局、操作纵排、状态省略与复制错误按钮。
- 便携包：只含白名单文件，数据目录为空，不包含个人状态或密钥。
- 启动器：PM2 已安装、仅有全局模块、PM2 缺失三种路径。

### 7.2 浏览器验收

在桌面和窄窗口分别验证：

- 侧栏中部独立滚动，顶部和底部不移动。
- 多模态表格不重叠，新增行可定位，操作列紧凑。
- Kling Omni 与 Seedance 4K 选项和 payload 一致。
- 状态不再撑高行，完整错误可复制。
- 主体选择窗口能逐项勾选素材，Seedance Prompt 前缀与参考编号一致。
- 刷新、重启服务后本机数据仍在；新浏览器或新用户首次打开为空。
