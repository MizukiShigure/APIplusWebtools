# MiniMax H3 模型扩展设计

日期：2026-07-30

## 1. 目标

把公司网关已开放的 `MiniMax-H3` 作为模型扩展接入现有两个任务页：

- 图文生视频：固定使用 H3 首尾帧模式。
- 多模态生视频：固定使用 H3 全能参考模式。

不新增独立 H3 页面，不替换或修改现有 Hailuo 02、Hailuo 2.3 和 Hailuo 2.3 Fast。请求继续通过左侧 `API Base` 指向的公司网关，不要求用户填写 MiniMax 官方 API Key。

## 2. 已确认的公司网关契约

当前公司站点前端使用以下路径：

- 创建任务：`POST /minimax_h3`
- 查询任务：`POST /minimax_h3_query`
- 查询请求体：`{ "task_id": "..." }`
- 模型值：`MiniMax-H3`

创建请求的公共字段为：

```json
{
  "prompt": "可选",
  "model_name": "MiniMax-H3",
  "generate_audio": true,
  "ratio": "9:16",
  "duration": 5,
  "resolution": "768P"
}
```

允许的参数：

- 比例：`adaptive`、`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`
- 清晰度：`768P`、`2K`
- 时长：5 到 15 秒的整数
- 默认值：`9:16`、`768P`、5 秒、生成声音开启

## 3. 共享模型契约

在 `model-contracts.js` 增加独立的 H3 契约，集中提供：

- `MINIMAX_H3` 能力常量。
- 首尾帧模式校验与 payload builder。
- 全能参考模式校验与 payload builder。
- 可见 `@1`、`@2` 素材编号到供应商标签的稳定映射。

`app.js` 的两个模型配置只负责把行数据交给共享契约，并声明当前页面使用的 H3 模式。创建路径、查询路径、模型版本、枚举和上限不在两处重复维护。

## 4. 图文生视频：首尾帧模式

模型列表新增 `海螺 H3`，版本只显示 `MiniMax H3`，值为 `MiniMax-H3`。

输入规则：

- 首帧图必填。
- 尾帧图可选。
- Prompt 可选。
- 比例、清晰度、时长必须属于 H3 枚举。
- 生成声音默认开启，用户可在参数列关闭。

请求在公共字段之外增加：

```json
{
  "first_frame_image": "https://cdn.example/first.png",
  "last_frame_image": "https://cdn.example/last.png"
}
```

没有尾帧时不发送 `last_frame_image`；空 Prompt 不发送 `prompt`。图文页现有选择、复制、上传、粘贴、拖放、队列、取消、结果和历史缓存交互保持不变。

## 5. 多模态生视频：全能参考模式

模型列表新增 `海螺 H3`，版本只显示 `MiniMax H3`，值为 `MiniMax-H3`。

输入规则：

- 图片、视频、音频合计最多 12 个。
- 已知时长的参考视频合计不得超过 15 秒。
- 音频不能单独作为参考，至少还要有一张图片或一段视频。
- Prompt、参考图片、参考视频三者至少提供一种。
- Prompt 可以为空，只要存在图片或视频参考。
- 生成声音默认开启，用户可关闭。

请求在公共字段之外按素材类型发送数组：

```json
{
  "reference_images": ["https://cdn.example/a.png"],
  "reference_videos": ["https://cdn.example/b.mp4"],
  "reference_audios": ["https://cdn.example/c.mp3"]
}
```

空数组不发送。素材沿用现有 `/fileupload` 上传流程和历史缓存 URL，不重复上传已经有 URL 的素材。

## 6. Prompt 素材引用

多模态页继续显示并插入 `@1`、`@2` 等可见编号。提交时根据参考栏最终顺序和素材类型转换：

- 第一张图片 -> `图片1`
- 第一段视频 -> `视频1`
- 第一段音频 -> `音频1`

例如参考栏顺序为图片、音频、视频时：

```text
让@1看向@3，使用@2的声音
```

提交为：

```text
让图片1看向视频1，使用音频1的声音
```

同时兼容公司站点已有的 `<<image_1>>`、`<<video_1>>`、`<<audio_1>>` 标记。无法识别的 `@` 文本原样保留，不误删用户内容。

## 7. 状态、轮询与历史

- 创建成功后沿用现有任务 ID 提取和本地并发队列。
- 查询统一走 `/minimax_h3_query`。
- 页面刷新后，已取得任务 ID 的 H3 任务继续查询，不重新提交。
- 30 分钟未返回时沿用现有超时规则。
- 生成记录保存任务类型、模型、版本、比例、清晰度、时长、Prompt、参考素材和声音设置。
- 从生成缓存“添加到生成队列行”时回到原任务类型，并恢复 H3 原参数。

## 8. 错误处理

提交前错误使用简短中文提示，不发送请求：

- 首尾帧模式缺少首帧。
- 全能参考模式没有 Prompt、图片或视频。
- 素材总数超过 12。
- 参考视频已知总时长超过 15 秒。
- 音频没有搭配图片或视频。
- 比例、清晰度或时长不在枚举内。

未知媒体时长不伪造结论，由公司后端继续校验。网关 4xx/5xx 保留完整原始错误和请求 ID，继续支持一键复制报错。

## 9. 测试与验收

自动测试覆盖：

- H3 创建和查询路径、模型值及全部枚举。
- 首尾帧 payload：必填首帧、可选尾帧、可选 Prompt、声音开关。
- 全能参考 payload：三类数组、12 个素材边界、15 秒视频边界、音频单独输入拒绝。
- `@` 编号按可见顺序正确转换为类型编号。
- 两个页面都出现 H3，且分别调用正确 builder。
- 切换模型后参数回退到 H3 合法值。
- H3 查询、刷新恢复、历史元数据和重新添加队列不回退到其他模型。

手工验收：

1. 图文生视频选择 H3，使用首帧和可选尾帧提交一条任务。
2. 多模态生视频选择 H3，混合图片、视频、音频并用 `@` 指定素材提交一条任务。
3. 在浏览器网络面板确认创建路径为 `/api/minimax_h3`，查询路径为 `/api/minimax_h3_query`。
4. 确认请求不包含供应商 API Key，且现有海螺模型行为未改变。

## 10. 非目标

- 不直连 MiniMax 官方 API。
- 不增加独立 H3 页面。
- 不为现有 Hailuo 02/2.3 增加全能参考能力。
- 不修改公司后端路由或供应商计费规则。
- 不在本次工作中重构其他模型或表格布局。
