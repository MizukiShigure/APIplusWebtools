# 数字人工作流整合设计

用户已于 2026-09-20 确认：正式整合至工作台，同用 4198 服务和共享数据目录；音色与形象推荐以手动绑定为主。

## 范围

- 新增独立的“数字人工作流”页面，保留现有“数字人”批量页和 4208 旧工具。
- 文本转语音、已有音频输入、音频调整、可灵/RunningHub 对口型和可选字幕连接为一个流程。
- 共享音色库、RunningHub 配置、数字人形象相册和形象-音色多对多绑定；选形象优先展示绑定音色，可指定默认音色，也支持反向筛选。
- 配置和记录以本地服务数据目录为准；浏览器只缓存读取结果，不整库覆盖；并发修改同一条目返回冲突。
- 图片原件保存在本地相册；远程生成视频仅保留 URL，音频处理和字幕确实需要的中间文件单独管理。
- 工作台与 Agent 通过同一套受保护的 localhost API 使用配置；Agent 可读、新增、提交任务，不可覆盖或删除已有库条目。
- 凭据只在服务端使用，普通配置读取返回已配置标记；不进入历史、Agent 响应、日志、源码和分发包。

## 模块边界

- `avatar-workflow-store.cjs`：版本化条目、原子持久化、秘密字段脱敏、相册文件、旧配置非破坏性导入。
- `avatar-workflow-media.cjs`：复用旧工具的公司网关 TTS、音频处理、数字人、RunningHub、字幕接口契约；依赖可配置并显式检测。
- `avatar-workflow-service.cjs`：鉴权路由、共享库、幂等流程任务、查询恢复、历史发布与依赖状态。
- `avatar-workflow-ui.js` / `.css`：在现有工作台 shell 中独立挂载的功能页，无第二端口和外部 iframe。
- 主工作台只增加导航、模块挂载和共享 RunningHub 配置适配；现有任务行和存储键保持兼容。

## 数据和权限

所有新增文件位于 `API_BATCH_DATA_DIR/avatar-workflow`。音色、工作流、相册、绑定关系按稳定 ID 读写，每条记录带 version。编辑需提交旧 version；成功原子写入，失败不替换原文件。删除只允许已认证的手动浏览器操作。凭据字段更新时缺失意味着保留，不以脱敏空值清除。空浏览器不得清空服务端已有库。

相册按内容 SHA-256 去重，限制类型、大小和路径。上传到远端时读取本地原图，通过公司网关或 RunningHub 的正常素材上传流程获取可访问引用，不把 localhost URL 传给模型。

旧工具目录和全局工作台 RunningHub 浏览器配置均采取一次性、可重试、保留原件的导入。发生 ID 冲突时不覆盖新库。导入前制作本地私有备份；私密文件不进入发布白名单。

## 执行和恢复

新流程任务由同一个本地服务运行，网页和 Agent 共用任务状态，切换页面不丢进度。创建远端任务前先写入 submitting 状态，得到 ID 后立即持久化；重启只查询已有远端 ID，不重复提交。无法确定是否已经创建成功的步骤标记为需人工检查。已完成步骤不重做。

任务发布到已有 history journal，携带流程 ID、音色/形象引用、提示词、输入和参数快照、来源及结果 URL。现有其他 Agent 模型继续使用浏览器执行器，不改变其契约。

## 依赖与降级

公司网关保持原地址和已实现契约。音频调整需要 FFmpeg，字幕需要 Python + 原字幕服务；新增依赖设置与状态，不绑定作者机器路径作为分发默认值。依赖缺失只禁用对应处理步骤，语音及数字人流程仍可用。不自动安装大型模型，不为测试提交收费任务。

## 验收

- 两个独立浏览器、Agent 读取到同一音色、工作流和相册；并发编辑不会静默覆盖。
- 新条目和手动绑定经重启后仍存在；删除不清理已有生成历史中的输入快照。
- 常规响应、历史、错误和 Agent 接口不泄露配置密钥；非本机/无令牌请求被拒绝。
- 使用模拟网关跑通 TTS → 数字人 → 字幕，刷新/重启不重复创建远端任务。
- 桌面及窄屏截图检查，相册分页/懒加载，长提示词及编辑焦点不因后台刷新跳动。
- 现有完整测试通过；便携构建白名单只增加代码、测试和文档，不含私有数据。
