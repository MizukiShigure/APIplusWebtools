# 本地部署与迁移

## 适用环境

- 完整便携包适用于 Windows 10/11 x64，内含经过校验的 Node.js 运行环境及许可证，无需安装 Node、npm、Git 或 PM2。
- 使用最新版 Edge / Chrome，解压到当前用户可写的普通目录，例如 `D:\APIplusWebtools`。没有 D 盘也可使用其他可写目录。
- 本地网页不等于离线生成。对方电脑必须能访问管理员私下提供的公司网关，具备公司要求的网络、账号权限和额度。包内不包含实际网关地址、作者账号或密钥。
- 仅支持本机访问，不开放局域网或公网。macOS、Linux、Windows ARM 不属于本次免安装包的验证范围。

## 第一次启动

1. 把 ZIP **完整解压**，不要在压缩软件中直接双击启动文件。
2. 双击根目录 `Start_API_Tool.bat`。无需管理员权限。首次启动会生成本机自己的 `data` 数据。
3. 浏览器自动打开 `http://127.0.0.1:4198/`。若未打开，手动访问该地址；不要直接打开 `index.html`。
4. 首次在左侧 API Base 填写管理员提供的网关地址，离开输入框后自动保存到本机私有数据目录的 `gateway.json`，网页与 Agent 共用。更新项目会保留该文件。RunningHub 如需使用，打开配置窗口填写自己的 API Key、工作流链接并导入相应 payload。预置节点模板不包含作者的工作流 ID。
5. 生图、图文生视频、多模态等模型沿用工作台配置，包括 Seedance 2.5、GPT Image 2.5 和海螺 H3。具体可用性取决于网关渠道，部署成功并不保证所有渠道始终有容量。
6. 手工页面任务执行期间保持页面打开。Agent CLI 任务由后台服务执行，不需要开浏览器；避免电脑休眠，已有任务 ID 应继续查询，不要盲目重新提交。
7. 用完后双击 `Stop_API_Tool.bat`。便携版使用后台 Node 进程，不需要 PM2；重启电脑后重新双击启动，不自动添加系统开机任务。

## 保存、更新与备份

- 完整便携包最初不带作者的任务、素材、历史、收藏、提示词或密钥。
- 服务端元数据保存在本包 `data`；浏览器任务行和部分设置仍在该浏览器的 localStorage / IndexedDB。仅复制 `data` 不是所有浏览器设置的完整备份。
- 历史缓存保存素材和结果 URL、提示词、参数、任务 ID 等元数据，不自动保存完整生成视频。远程 URL 可能失效，重要结果应单独下载。
- 尽量一直用同一个浏览器、`127.0.0.1` 和端口。改成 `localhost` 或换端口会切换浏览器存储空间。
- 升级前停止服务，备份整个 `data` 目录。新版本解压到新目录，把自己的 `data` 复制到新包，确认后再启动；保留旧包及旧数据备份，不要混装源码或从空包覆盖已有数据。
- 如需将数据长期独立放在 D 盘，在 PowerShell 中先设环境变量再启动，以后启动也必须沿用这个变量：

```powershell
$env:API_BATCH_DATA_DIR = 'D:\APIplusWebtools-data'
& .\Start_API_Tool.bat
```

已有数据不会因设置路径而自动搬迁。迁移时先停止服务，复制整个原数据目录，再配置新路径；不要只复制 `history.json`。

ZIP 是版本快照，不带 Git 历史。需要拉取更新的开发者应另行 Git clone；本地 VERSION 不表示相同版本已发布到远程仓库。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 页面打不开 | 确认已完整解压、`runtime/node.exe` 存在且未被安全软件隔离；检查 `data/logs/server.err.log`。不要关闭系统安全防护。 |
| 端口被占用 | 不结束未知程序。先确认是不是已有工作台在运行；需要另开时在 PowerShell 设置 `$env:PORT='4300'` 后启动，关闭时沿用同一端口。 |
| 页面正常但生成失败 | 检查公司网络、VPN/代理的授权配置、网关权限和额度。403/401 属于授权问题，400 常为参数错误，500/无可用渠道通常是上游问题。不要通过批量重试验证。 |
| Agent 一直等待执行器 | 检查本地服务版本、`capabilities` 与任务状态；受支持的后台模型不需要开网页。不要为解决等待而重复提交。 |
| 历史看起来为空 | 检查浏览器、hostname、端口以及 `API_BATCH_DATA_DIR` 是否改变；备份数据后再诊断，勿点清空或写入空历史。 |
| 突然断电/刷新 | 用已有任务 ID 继续轮询。未确认远端是否创建成功时不要重复提交，以免重复计费。 |

诊断时给对方 Agent 阅读 `docs/AGENT_DEPLOYMENT.md`。日志可能含本机路径或错误信息，分享前检查，不上传自己的 `data` 或浏览器导出。

## 两种 Agent 技能

- `api-plus-agent` 完整技能包包含干净的工作台、Node 和许可证。安装到对方 Agent 的技能目录后，执行 `scripts/run-workbench.ps1 capabilities`，会校验并解压工作台、隐藏启动服务；无需本机令牌配置或打开浏览器。
- `local-api-workbench` 轻量技能仅用于已确定安装路径的本机。它不含工作台与运行环境，执行 `scripts/workbench.ps1 capabilities` 调用已有安装。

每个 Agent 设置自己的来源名称和任务 ID，使用 `upload` 录入原始素材，再 `submit`。后台保存原文件名/路径/哈希、素材信息、Prompt、参数和结果；网页历史稍后打开也能查看。使用 `history --task-id <id>` 查记录、`recreate <id>` 重新抽卡。完全相同的提交重试不会重复创建任务。
